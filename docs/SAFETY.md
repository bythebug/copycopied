# Safety rules: how each one is enforced and tested

Status as of Phase 3 (2026-10-27). "Test" names refer to `Tests/BackedCoreTests`. "Manual" means it was checked with `scripts/make-fake-card.sh` disk images.

| # | Rule | Enforced by | Tested |
|---|---|---|---|
| 1 | **Cards are read-only** | Card files are only ever opened with `O_RDONLY \| O_NOFOLLOW` (`Hash.swift`, `Copier.writePartial`). Scanning only enumerates and calls `lstat`. Nothing in BackedCore writes to, renames or deletes anything under a card root. A copy destination on any mounted card is refused twice: `Offload.refuseCardFolder` before matching (a card compared with itself looks green), and `Copier.readOnlyRoots` before anything touches the disk, including the partial sweep. The app only makes a folder's drive the working drive after that check. | `neverWritesIntoACard`, `cardFolderIsRefusedBeforeMatching`. Manual: `copy --to "/Volumes/Card A/backup"` and `status --drive "/Volumes/Card A"` are refused and the card is unchanged. Manual: reading a card file on an exFAT image left its atime unchanged (macOS mounts exFAT `noatime`). **Gap:** macOS itself writes `.fseventsd` on any writable mount, and an AppleDouble `._DCIM` was also seen on the fake card (possibly from the test script creating that folder). Decision (PLAN.md D7): **no read-only remount.** The user wants to keep deleting from Finder. Rule 1 is therefore enforced for backed.'s own actions only; files macOS or Finder add to a writable card (`.fseventsd`, `.Spotlight-V100`, `._*`, `.DS_Store`) are outside backed.'s control. backed. ignores them during scans. |
| 2 | **Green means verified** | `Verdict.from` returns `.backed` only when every check is for a connected drive with zero missing files. A file counts only if a destination file has the same size **and** xxh3-128. Destination hashes are always computed with `F_NOCACHE`. The copier writes with `F_NOCACHE` set, runs `F_FULLFSYNC`, then re-reads uncached and compares. A cached index hash is trusted only while `(size, mtime, inode)` re-stat'd this check still matches. | `allCopiedIsGreen`, `changedDestinationFileIsRehashed`, `copiedThenMatchedIsGreen`, `bitFlipIsCaughtAndNamed`. **Gap:** whether `F_NOCACHE` read-back truly reaches the device instead of still-cached pages hasn't been measured. TODO(verify) on real hardware. |
| 3 | **Memory is never proof** | A disconnected drive (`Destination.root == nil`) can only produce `.fromMemory` (grey), never `.backed`. Unhashed rows on a disconnected drive can't vouch for a file. | `memoryIsNeverGreen`. Manual: unplugging the T7 image gave "From memory — T7 Shield as of …". |
| 4 | **Never overwrite** | `Copier.place` uses `renamex_np(…, RENAME_EXCL)`, which fails instead of replacing. On a clash with different content it tries `name (2).ext`, `(3)`, …. Identical content already at that name is left alone. On filesystems without `RENAME_EXCL` it checks before renaming (marked `ponytail:`; racy only if something else writes the same name). | `neverOverwritesAClash`, `caseInsensitiveClashIsNumbered`, `identicalFileAtNameIsNotDuplicated`. Manual: Card B's `MVI_0001–0019` became `(2)` beside Card A's files on APFS. |
| 5 | **Match by content** | `Matcher` compares size, then xxh3-128. Path and name are never used. `walkFiles` must see every file: a junk *file* (`.DS_Store`, `._*`) once made it skip its whole folder, which could drop card files from a scan and give a false green. Fixed in Phase 3. | `sameNameDifferentContentIsMissing_renamedCopyIsBacked`, `junkFilesDoNotHideTheirFolder`. Manual: hand-copied files in other folders counted as backed. |
| 6 | **Atomic copies** | Each write goes to `<name>.backed-partial` (opened `O_EXCL`), is synced with `F_FULLFSYNC` (falling back to `fsync`, logged), verified, then renamed. A `defer` unlinks the partial on every exit path. A batch first sweeps leftover partials from its target folders. Partials are never indexed or matched. | `bitFlipIsCaughtAndNamed`, `cancelMidCopyLeavesNoPartial`, `stalePartialFromCrashIsReplaced`, `leftoverPartialsInTargetFolderAreSwept`, `partialFilesOnDestinationDoNotCount`. Manual: force-detaching the drive mid-copy left one partial (the drive was already gone). The next run removed it and finished green. |
| 7 | **No surprises: log everything** | `CopyLog` writes JSON lines for every folder created, file copied (source, destination, size, xxh3_128), re-copy, partial removed, fsync fallback and failure. CLI logs go to `~/Library/Application Support/backed/logs/`. Per-shoot log placement comes in Phase 4. | `logRecordsFoldersAndCopies`. |

## Other protections
- **Free space and FAT32:** `Copier.preflight` refuses to start if the batch doesn't fit, or if any file is ≥ 4 GiB on `msdos` (FAT32). Test: `preflightStopsBeforeStarting`. Manual: refused on a too-small exFAT image.
- **Card read twice:** when a `CopyRequest.expectedHash` (from an earlier independent read) differs from the hash taken while copying, the copy fails. Test: `sourceThatReadsDifferentlyFails`.
- **Sleep:** an IOKit `PreventUserIdleSystemSleep` assertion is held while copying. Closing the lid still sleeps the Mac, and resume covers that. Not yet tested.
